# 拡張ロードマップ（提案）

[DESIGN.md](DESIGN.md) に記載した現状実装を前提に、今後の拡張候補を
優先度別に整理したもの。決定事項ではなく提案であり、着手前に個別に相談する。

## 実装済み（ベースライン強化・完了分）

- **経験リプレイ + ミニバッチ学習**: 1局ごとの生データで即学習する方式から、
  `ReplayBuffer` に蓄積してランダムサンプルしたミニバッチで学習する方式へ変更
- **盤面対称性によるデータ拡張**: 回転・鏡映で1局面を8通りに水増し

## 提案1: 探索の導入（優先度: 高）

- **内容**: `choose_move` の1手読みを、価値ネットを葉評価に使う
  ミニマックス + αβ枝刈り、または簡易モンテカルロ木探索（MCTS）に置き換える
- **効果**: 終盤の読み抜けが減り、対人戦での手応えが明確に上がる。現状の
  最大の弱点（1手先しか見ない）に直接効く
- **コスト / トレードオフ**: 実装量は中程度。探索深さ・ノード数を上げるほど
  自己対戦・対局の1手あたりの計算時間が増える
- **依存関係**: 他の提案なしでも単独で着手可能。既存の `choose_move` を
  置き換えるだけで良い

## 提案2: 方策ヘッドの追加（優先度: 中、探索と組み合わせて効果大）

- **内容**: `ValueNetwork` に、局面評価（value）に加えて着手確率分布
  （policy）を出力する2つ目の出力ヘッドを追加する（AlphaZero方式）
- **効果**: MCTSの事前確率として使うと探索の効率が大きく上がる。方策自体を
  教師信号（実際に選ばれた手）で学習することで、価値関数だけよりも学習が
  安定・高速化する可能性がある
- **コスト**: ネットワーク構造・学習ループ・自己対戦のデータ収集ロジックの
  変更が必要。**提案1（探索）とセットでないと恩恵が小さい**

## 提案3: リーグ戦self-play（優先度: 中）

- **内容**: 直近の自分自身だけでなく、過去の複数チェックポイントを対戦相手
  プールとして保持し、ランダムに選んで自己対戦させる
- **効果**: 特定の戦略にだけ強くなって別の戦略に弱くなる「循環的な忘却」
  （じゃんけんのように AがBに勝ち、BがCに勝ち、CがAに勝つ状態）を防ぎ、
  より汎用的に強いエージェントに近づく（AlphaStarのリーグ方式と同様の発想）
- **コスト**: チェックポイントの保存・管理、対戦相手プールの選択ロジックの
  実装が必要。自己対戦1局あたりの計算量は変わらない

## 提案4: 特徴量の強化（優先度: 低〜中、手軽に着手可能）

- **内容**: `agent.encode` に、辺の安定石（ひっくり返されない石）判定や、
  角に繋がる着手かどうかなど、より質の高い手作り特徴量を追加する
- **効果**: README に元々あった提案で、学習の立ち上がりが速くなることが
  期待できる。他の提案より実装コストが小さい
- **コスト**: 低い。`encode` 関数と `FEATURE_DIM` の変更のみで完結する

## 提案5: CNNベースのネットワーク（優先度: 低、大掛かり）

- **内容**: 全結合MLPから、盤面を2次元のまま扱う畳み込みネットワークに
  置き換える
- **効果**: 辺・角の形状といった空間的パターンをより自然に学習できる
- **コスト**: NumPyのみでの畳み込み・逆伝播の実装は手間が大きい。
  フレームワーク（PyTorch等）の導入も検討対象になり、「NumPyだけで実装」
  というプロジェクトの現在の方針から外れる判断が必要

## 提案6: 学習の並列化（優先度: 低）

- **内容**: 複数プロセスで自己対戦を並列実行し、経験（学習データ）を集約する
- **効果**: `--episodes` を増やす際の学習時間短縮
- **コスト**: マルチプロセス管理、ネットワーク重みの同期方法の設計が必要。
  学習の質そのものは向上しない（速度改善のみ）

## 優先順位の目安

| 提案 | 効果 | 実装コスト | 前提 |
|---|---|---|---|
| 1. 探索の導入 | 大 | 中 | なし |
| 4. 特徴量の強化 | 中 | 小 | なし |
| 3. リーグ戦self-play | 中 | 中 | なし |
| 2. 方策ヘッド追加 | 大（探索とセット） | 中〜大 | 提案1推奨 |
| 6. 学習の並列化 | 速度のみ | 中 | なし |
| 5. CNN化 | 中〜大 | 大 | 方針変更を伴う |

次に着手するなら、コストと効果のバランスから **提案1（探索）** または
**提案4（特徴量強化）** が候補になる。
